# KAORI Website v0.1.3

This release improves the public KAORI Website's release communication,
contributor guidance and operational reliability. It keeps the familiar public
website experience while making stable releases easier to understand and verify.

## Highlights

Visitors and maintainers can find the latest published stable release through
a corrected dynamic README badge. Future stable release announcements lead with
a short, human-reviewed explanation of changes, while release provenance and
deployment evidence remain available in a separate technical section.

## Improvements

- Documents the Website's single-public-slot release model, including its
  explicit staging, Human UAT, protected promotion and production approval gates.
- Adds an issue-first contributor guide with an isolated fork feedback path,
  while keeping untrusted contributions out of privileged release runners.
- Provides a read-only release-notes preview and version-specific reviewed
  summaries, rather than publishing internal pull-request titles as release
  notes.
- Simplifies the protected production-release request to one stable-version
  input, without weakening signed image, UAT, rollback or independent approval
  requirements.
- Reconciles the published stable changelog history and makes the release
  process more traceable.

## Fixes

- Corrects an unsupported query parameter that displayed an error in the
  README's latest-stable-release badge.
- Fixes the generated release-notes preview command so it works against the
  reviewed staging candidate without creating a tag or release.
- Tightens release configuration and protected Environment handling, including
  explicit production invocation rather than stable publication on a normal
  `main` push.

## Known Limitations

- The public KAORI Website introduces the platform; it is not the authenticated
  KAORI Application or a live infrastructure operations dashboard.
- Staging and production release governance currently share one public Website
  runtime. This release does not provision a second server or a separate public
  UAT domain.
- Source and documentation changes do not necessarily change the immutable
  website image. A stable release retains the already accepted, signed release
  candidate image and its original build identity; it does not rebuild or
  retag the application.
- External contributor adoption remains controlled pending the separate KAORI
  community and rights acceptance gates.
